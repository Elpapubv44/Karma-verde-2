--- PROMPT #24: "Olvide mi contrasena" / recuperacion ---
1. En `index.tsx`, agrega un link "Olvide mi contrasena" debajo del formulario de login.
2. Crea una ruta `/recuperar` con un formulario que pida email.
3. En backend, crea `php-api/auth/recuperar.php` que:
   - Valide el email exista.
   - Genere un token unico de 32 chars con `bin2hex(random_bytes(16))`.
   - Guarde el token en tabla `password_resets` con expiracion de 1 hora.
   - Envie email (o simula en logs) con link de reset.
4. Crea `php-api/auth/reset.php` que valide el token y permita nueva contrasena.

--- PROMPT #25: "Recordarme" / persistencia de sesion ---
1. En `index.tsx`, agrega un checkbox "Recordarme".
2. Al hacer login con "Recordarme" marcado, el backend debe setear la cookie de sesion con `expire` de 30 dias.
3. En frontend, en vez de `localStorage` solo, usa una estrategia hibrida: guarda un `refreshToken` en `localStorage` y el `accessToken` en memoria.
4. Implementa un interceptor en `api.ts` que renueve el accessToken automaticamente cuando expire.

--- PROMPT #26: Verificacion de email ---
1. En `php-api/auth/register.php`, despues de crear el usuario, genera un `verification_token`.
2. Guarda el token en la tabla `usuarios` (columna `email_verified_at` y `verification_token`).
3. Envia email (o loguea) con link `/verificar?token=XYZ`.
4. Crea `php-api/auth/verificar.php` que valide el token y marque `email_verified_at = NOW()`.
5. En frontend, bloquea funcionalidades clave (canje, escaneo) hasta que el email este verificado.

--- PROMPT #27: Logout explicito en frontend ---
1. En `AppShell.tsx` o en un menu de usuario, agrega un boton "Cerrar sesion".
2. Al hacer click, llama a `apiFetch('/auth/logout', { method: 'POST' })`.
3. Limpia `localStorage`, resetea el store de Zustand a estado inicial, y redirige a `/`.
4. Asegurate de que el backend `php-api/auth/logout.php` destruya la sesion con `session_destroy()`.

--- PROMPT #28: Proteccion CSRF en endpoints PHP ---
1. En cada endpoint PHP, al inicio de sesion genera un token CSRF: `$_SESSION['csrf_token'] = bin2hex(random_bytes(32))`.
2. En frontend, en `api.ts`, lee el token de una cookie o endpoint `/auth/csrf` y envialo en header `X-CSRF-Token`.
3. En cada endpoint PHP que reciba POST/PUT/DELETE, valida: `if (!hash_equals($_SESSION['csrf_token'], $_SERVER['HTTP_X_CSRF_TOKEN'])) { http_response_code(403); exit; }`.

--- PROMPT #29: Rate limiting en login ---
1. En `php-api/auth/login.php`, implementa rate limiting por IP:
   - Usa `$_SERVER['REMOTE_ADDR']` como clave.
   - Guarda en `$_SESSION` o en una tabla `login_attempts`: `intentos`, `ultimo_intento`.
   - Si hay mas de 5 intentos fallidos en 15 minutos, retorna `429 Too Many Requests`.
   - Resetea el contador tras un login exitoso.
2. En frontend, muestra un mensaje amigable cuando reciba 429.

--- PROMPT #30: Historial de sesiones / dispositivos activos ---
1. Crea tabla `sessions`: `id`, `user_id`, `device_info`, `ip_address`, `created_at`, `last_active`.
2. En cada login, inserta un registro en `sessions`.
3. Crea endpoint `php-api/auth/sessions.php` que liste sesiones activas del usuario.
4. Permite al usuario eliminar/revoke sesiones especificas desde su perfil.

   ```php
       session_start();
       if (!isset($_SESSION['user'])) {
         http_response_code(401);
         echo json_encode(['error' => 'No autenticado']);
         exit;
       }
       if (!empty($requiredRoles) && !in_array($_SESSION['user']['rol'], $requiredRoles)) {
         http_response_code(403);
         echo json_encode(['error' => 'Rol insuficiente']);
         exit;
       }
       return $_SESSION['user'];
     }
   }
   ```
